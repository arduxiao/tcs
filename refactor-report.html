① ES Modules 替代 IIFE 全局模式

模块化
index.html — 脚本标签 index.html L137–140

原代码依赖手动排序保证加载顺序（data → auth → game → app）。ES Module 的 import 声明由引擎自动解析依赖图，HTML 只需声明入口。

重构前（4 个标签，顺序不能错）重构后（1 个入口）
<!-- 脚本加载顺序：依赖在前 -->

<script src="js/auth.js"></script>
<script src="js/game.js"></script>
<script src="js/app.js"></script>
<!-- ES Module：依赖由 import 自动解析 -->

type="module" 脚本自动 defer（HTML 解析完才执行），故 app.js 中顶层代码可直接访问 DOM，无需 DOMContentLoaded 包裹。
data.js — IIFE 全局对象 → 具名 export js/data.js

IIFE 模式通过闭包隐藏内部变量，但仍然污染全局作用域（window.DataStore）。ES Module 文件天然隔离，只有 export 的内容才对外可见。

③ requestAnimationFrame 替代 setInterval

性能提升
game.js — 游戏主循环 js/game.js #scheduleTick

setInterval 的问题：固定毫秒间隔，与显示器刷新率无关，可能在两次屏幕刷新之间触发多次（渲染浪费）或完全错开屏幕刷新（画面撕裂）。标签页不可见时仍然执行（浪费 CPU）。
requestAnimationFrame 的优势：与屏幕刷新率同步（通常 60fps = 16.67ms/帧）；标签页不可见时自动暂停；由浏览器在最优时机调用渲染。
游戏逻辑（蛇移动）仍按难度控制频率，通过时间戳节流实现；渲染每帧都执行，粒子动画因此更流畅。

重构前（setInterval，逻辑与渲染耦合）重构后（rAF + 时间戳节流，逻辑与渲染解耦）
// 启动：每 100ms tick 一次
interval = setInterval(
  _tick,
  SPEED[difficulty]
);

function _tick() {
  if (paused || gameOver) return;
  // 1. 推进逻辑
  direction = nextDirection;
  // ... 碰撞检测、移动 ...
  // 2. 渲染（与逻辑在同一函数）
  _render();
}

// 停止
clearInterval(interval);
// 启动：rAF 驱动，时间戳控制频率
#scheduleTick() {
  const tickMs = SPEED[this.#difficulty];
  const frame = (now) => {
    if (!this.#running) return;
    // 逻辑：按难度频率推进
    if (now - this.#lastTick >= tickMs) {
      this.#advanceLogic();
      this.#lastTick = now;
    }
    // 渲染：每帧都执行（60fps）
    this.#render();
    this.#rafId = requestAnimationFrame(frame);
  };
  this.#rafId = requestAnimationFrame(frame);
}

// 停止
cancelAnimationFrame(this.#rafId);
#advanceLogic() 和 #render() 完全解耦：逻辑按游戏速度推进，渲染每帧执行——吃食物时的粒子特效在 60fps 下更平滑，而蛇的移动速度不受影响。

④ Bug 修复：auth-toggle 事件监听器内存泄漏

Bug 修复
app.js — 登录/注册切换按钮的事件绑定 js/app.js L62–93（原）→ L63–69（重构后）

原代码每次切换登录/注册模式时，都会重新 innerHTML 整个 authSwitch，再重新 addEventListener。 旧的监听器没有被移除，每切换一次就多一个监听器——切换 N 次后有 N 个监听器同时响应，导致状态混乱和内存泄漏。 事件委托用一个永久监听器监听父元素，通过 e.target.id 判断点击目标，完全避免重复绑定。

重构前（每次切换都重新绑定，内存泄漏）重构后（事件委托，一个永久监听器）
// 每次点击都执行：

  isLoginMode = !isLoginMode;
  // 重写 innerHTML（销毁旧节点）
  authSwitch.innerHTML =
    '还没有账号？<a id="auth-toggle">...</a>';
  // 又绑定一次（旧监听器已泄漏）
  document.getElementById('auth-toggle')
    .addEventListener('click', () => { ... });
  _rebindToggle(); // 再绑一次...
});

function _rebindToggle() {
  const newToggle =
    document.getElementById('auth-toggle');
  newToggle.addEventListener('click', () => {
    // 第 N 次切换时这里有 N 个监听器！
  });
}
// 只绑定一次，永远不需要重绑
authSwitch.addEventListener('click', (e) => {
  // 事件委托：检查实际点击的元素
  if (e.target.id !== 'auth-toggle') return;

  isLoginMode = !isLoginMode;
  authMsg.textContent = '';
  authMsg.className = 'auth-msg';
  updateAuthUI(); // 只更新 UI 文字
});

function updateAuthUI() {
  authSubmitBtn.textContent =
    isLoginMode ? '登 录' : '注 册';
  authSubtitle.textContent =
    isLoginMode ? '登录后开始游戏' : '创建账号';
  authSwitch.innerHTML = isLoginMode
    ? '还没有账号？<a id="auth-toggle">注册</a>'
    : '已有账号？<a id="auth-toggle">登录</a>';
  // 不需要重绑事件，父元素监听器仍有效
}
innerHTML 替换子节点后，子节点上的监听器随节点一起销毁。但父元素 authSwitch 的监听器仍然存在，通过 e.target 判断点击目标，所以永远不需要重新绑定。

空值合并 ?? 替代 || js/data.js

|| 对所有假值（0、''、false）都会取右值，?? 只在左值为 null 或 undefined 时才取右值，语义更精确。

重构前重构后

return _get(KEYS.LOGIN_HISTORY) || {};

  .sort(...);
return _get(KEYS.USERS) ?? {};

return _get(KEYS.LOGIN_HISTORY) ?? {};

return (records[username] ?? [])
  .sort(...);

Math.imul 替代手写整数乘法 js/auth.js _hashPassword

原代码用 (hash << 5) - hash 模拟 hash * 31，再用 hash = hash & hash 强制转 32 位整数，意图正确但写法晦涩。Math.imul(31, hash) 是标准的 32 位整数乘法，语义清晰。

重构前重构后
for (let i = 0; i < password.length; i++) {
  const char = password.charCodeAt(i);
  hash = ((hash << 5) - hash) + char;
  hash = hash & hash; // 转 32 位整数
}
for (const char of password) {
  hash = Math.imul(31, hash)
       + char.charCodeAt(0) | 0;
  // Math.imul 原生 32 位整数乘法
  // for...of 直接迭代字符，更语义化
}
| 0 与原来的 & hash 效果相同（截断为 32 位有符号整数），但写法更标准。

⑥ Object.freeze 保护常量

防御性编程
game.js / data.js — 常量对象冻结

原代码的 DIR、SPEED、FOOD_ICONS、KEYS 等常量对象，虽然用 const 声明，但对象内部的属性仍可被修改（const 只保护引用，不保护内容）。Object.freeze() 让对象深度不可变，任何修改都被静默忽略（严格模式下抛错）。

重构前（const 不保护属性）重构后（freeze 保护内容）
const DIR = {
  UP:    { x: 0, y: -1 },
  DOWN:  { x: 0, y:  1 },
  // ...
};
// DIR.UP = null; ← 不报错！
const DIR = Object.freeze({
  UP:    { x: 0, y: -1 },
  DOWN:  { x: 0, y:  1 },
  // ...
});
// DIR.UP = null; ← 严格模式抛 TypeError
