JS 代码中从未写过 new Document()，但 document 始终存在——它来自浏览器引擎，不来自任何 JS 文件

JS 运行环境
你的 JS 代码
直接使用 document、window、localStorage 等，不需要 import 或 new，因为引擎启动时已经注入完毕。
类比：你打开终端就能用 cd、ls，不需要先安装它们——shell 启动时内核已经提供好了。浏览器引擎对 JS 做的是同样的事。
document 对象
document 对象在浏览器开始解析 HTML 之前就已由 Blink 用 C++ 创建，并通过 V8 注入为 JS 全局变量
浏览器预置的全局对象（JS 代码不需要、也不能 new 它们）
window — 全局作用域本身
document — 当前页面 DOM 树的根
localStorage — 持久存储 API
console — 控制台输出
Math — 数学工具（ECMAScript 内置）
Date — 时间对象（ECMAScript 内置）
前两行（window / document / localStorage / console）是 Web API，由浏览器引擎提供；后两行（Math / Date）是 ECMAScript 规范内置，由 V8 自身提供。两者的来源不同，但对 JS 代码来说使用方式完全一样——都是"拿来即用"的全局变量。

// EventTarget 接口（Web API 规范定义，Blink C++ 实现） EventTarget.prototype.addEventListener(type, listener, options) EventTarget.prototype.removeEventListener(type, listener) EventTarget.prototype.dispatchEvent(event) // 因此以下写法全部合法： document.addEventListener(...) // Document 继承自 EventTarget document.body.addEventListener(...) // HTMLElement → Element → Node → EventTarget window.addEventListener(...) // Window 也实现了 EventTarget
JS 里的 document.addEventListener('DOMContentLoaded', cb) 本质是：通过 V8 绑定层，调用 Blink C++ 里 EventTarget::addEventListener() 方法，把回调函数 cb 的引用注册到 document 节点的事件监听器列表中。
DOMContentLoaded
触发机制
DOMContentLoaded 不是 JS 代码触发的，JS 代码只是在「等通知」；真正的触发者是 Blink 渲染引擎的 C++ 层
谁触发：浏览器引擎（Blink C++），不是任何 JS 代码
// 这是浏览器 C++ 内部的伪代码（简化）： void HTMLParser::finishedParsing() { // HTML 解析完毕，同步脚本全部执行完 document->dispatchEvent(Event::create("DOMContentLoaded")) // ↑ 这一行触发事件，JS 里注册的所有回调被依次调用 } // 你在 app.js 里写的： document.addEventListener('DOMContentLoaded', () => { ... }) // 只是往上面那个监听器列表里"插了一张回调卡" // 等 C++ 调用 dispatchEvent 时，V8 再把你的回调拿出来执行
对比两个相似事件的触发时机：
事件触发时机等待内容本项目是否使用
DOMContentLoaded HTML 解析完 + 同步脚本执行完 不等图片、CSS、异步脚本 ✓ app.js L5 使用
window.load 页面所有资源全部加载完毕 等图片、iframe、样式表等 ✗ 本项目未使用
本项目选 DOMContentLoaded 是正确的——它只需要 DOM 节点可以 getElementById，不依赖图片，启动更快。
完整链路
从「浏览器内核」到「app.js 第一行代码执行」的完整链路
① Blink C++：分配 Document 对象，通过 V8 绑定注入全局变量 document ② app.js 加载执行：document.addEventListener('DOMContentLoaded', cb) └─ 实际调用 Blink C++ 的 EventTarget::addEventListener() └─ 把 cb（回调函数引用）存入 document 的监听器列表 ③ Blink C++：完成 HTML 解析 + 所有同步脚本 └─ 调用 document->dispatchEvent("DOMContentLoaded") └─ V8 拿出监听器列表中的 cb，执行它 ④ cb 开始执行 = app.js L5 的箭头函数体开始运行
JS 代码始终处于「被动」位置——注册回调，等待引擎通知。真正驱动一切的是浏览器 C++ 引擎。
